# Data — current working dataset v1

We use SpreadsheetBench Verified, distributed through the [official dataset repository](https://huggingface.co/datasets/KAKA22/SpreadsheetBench). The downloaded archive contains 400 tasks, each with an initial workbook and a reference workbook. We record the archive SHA-256 and per-workbook hashes. The source metadata contains 275 cell-level and 125 sheet-level tasks. All 400 tasks passed checks for required metadata, unique identifiers, paired files, and readable workbook XML. These structural checks do not establish semantic correctness of the reference answers or compatibility with the final evaluator.

To reduce leakage from shared workbooks, we first checked input-byte hashes and normalized input-cell hashes. No exact shared workbooks were identified. We then screened all 79,800 task pairs using shared text and cell-content overlap. Sixty-three candidate pairs were reviewed. Common vocabulary such as months, names, and generic headers was not treated as sufficient evidence for merging source families. Seven pairs involving 13 tasks retained uncertain lineage, including shared dictionary material and distinctive business records. We conservatively excluded those 13 tasks; the per-pair evidence and exclusion reasons are preserved. No source-family merges are asserted from similarity alone.

Using deterministic, family-preserving selection on the remaining 387 tasks, we fixed a working subset of 120 tasks: 60 development, 30 validation, and 30 test. The subset contains 82 cell-level and 38 sheet-level tasks. The 267 remaining eligible tasks are logged as not selected, separately from the 13 lineage-uncertainty exclusions and zero structural rejections. The selected tasks are observed singleton families under the documented procedure. Hash ordering and seed details are recorded in the provenance file, and selection did not use model outcomes or reference-answer values.

The split validator checks task uniqueness, required allocation, and absence of cross-split observed-family and input-hash overlap. All 240 selected workbook hashes and final manifest checksums were verified. Input workbooks and evaluator-only reference workbooks are stored separately. The executor must not have access to references or the original archive. Metadata such as answer ranges is preserved for benchmark evaluator integration.

This family screen does not prove statistical independence and may miss transformed workbook variants. Excluding uncertain sources may affect representativeness. We will retain the fixed version and report any later changes explicitly rather than silently resampling after model evaluation.

The planned feedback collection consists of two attempts per development task, or 120 original attempts; the newer tracker additionally proposes 24 reruns on four dominant tasks. These are plans, not collected observations. As of preparation, the executor/model and API budget remain undecided, and C1/C2/C3 definitions require clarification. No model-success counts, feedback pools, or performance results are claimed. When actual evaluator-labelled attempts are available, the pool builder will preserve original identities, distinguish injected copies, enforce development-only membership, and report outcome proportions and source concentration.
